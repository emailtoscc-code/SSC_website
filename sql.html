Introduction to Databases and SQL

What is SQL?

SQL stands for Structured Query Language

In simple words, it is the standard language used to talk to a database so you can store, find, change, or organize data.

In A Simple Analogy

Think of a database like a massive D-Mart godown or a giant digital Kirana store ledger:

  • Instead of physical goods, it stores digital information (like customer names, bank account details, Zomato orders, or college exam marks).
  • A database can hold millions of records, making it impossible to check manually page-by-page.
  • SQL is the exact language or instruction you give to the store manager to get what you want instantly. For example, telling the manager: "Show me the bill details of all customers from Delhi who spent more than 5,000 rupees today."

Key Things to Know About SQL:

What it does: It lets you access and manipulate databases (viewing data, adding new data, updating details, or deleting old records).

Universally Accepted: It is a globally recognized standard. It was approved by the ANSI (American National Standards Institute) in 1986 and the ISO (International Organization for Standardization) in 1987. This means once you learn SQL, you can use it across almost any database system in the world (like MySQL, PostgreSQL, or Oracle).

Database Management Operations

  • 🔍 Run queries  against a database
  • 📥 Fetch (retrieve) data  from a database
  • ➕ Insert new records  into a database
  • ✏️ Update existing records  in a database
  • 🗑️ Delete records  from a database
  • 🗄️ Create brand new databases
  • 📋 Create new tables  inside a database
  • ⚙️ Create stored procedures  to handle business logic
  • 👁️ Create views  to simplify complex queries
  • 🔒 Manage access and permissions  on tables, procedures, and views

SQL is a Standard — But Wait...

Even though SQL is an official ANSI/ISO standard, different database systems use their own flavors or versions of the SQL language.

💡 The Good News:

To stay compliant with the standard, almost all versions support the main commands—like SELECT, UPDATE, DELETE, INSERT, and WHERE—in a very similar way.

  • 🗄️ An RDBMS database program  (i.e. MS Access, SQL Server, MySQL)

  • 🔍 SQL  to get the data you want

SQL Statement: Select Records

SELECT * FROM Employees;
Simple Explanation:
  • SELECT *: This tells the database that you want to fetch all columns (all details like name, address, phone number, etc.) from the table.
  • FROM Employees: This specifies that the data should be taken from the table named "Employees".
🚀 Result: Running this simple command will show you every single record present inside your Employees table!

Basic SELECT Syntax

Select All Columns

EXAMPLE

Filtering Data with WHERE Clause

The WHERE clause is used to filter records based on specified conditions.

WHERE Clause Syntax

SELECT column1, column2, ... FROM table_name WHERE condition;


SQL Query Example

SELECT column1, column2, ...
FROM table_name
WHERE condition;
EXAMPLE
-- Filter by city SELECT * FROM customers WHERE city = 'New York'; -- Filter by age SELECT * FROM customers WHERE age > 25; -- Filter by multiple conditions SELECT * FROM customers WHERE city = 'New York' AND age > 25;

Text Fields vs. Numeric Fields in SQL

When writing SQL queries, you need to be careful about where you use quotes (' '):

📝 Text Values

Requires single quotes (e.g., 'Delhi' or 'Rahul').

🔢 Numeric Values

Numbers should never have quotes (e.g., 1, 100).

Example Query

SELECT * FROM Customers
WHERE CustomerID = 1;

💡 Quick Note: Because CustomerID is a number, we use = 1 without quotes. If it were text, it would be City = 'Delhi'.

Operators in The WHERE Clause

You can use various operators other than just the equals = operator to filter your search results effectively.

⚡ Comparison Operators

Use operators like > (greater than), < (less than), or != (not equal) for flexible filtering.

🎯 Exact Match

Use the standard = operator when you need to match an exact, specific value.

Example

Select all customers who have a CustomerID greater than 80:

SELECT * FROM Customers
WHERE CustomerID > 80;

💡 Pro Tip: Choosing the right filtering operator helps optimize database query performance.

EXAMPLE

LIMIT Clause

The LIMIT clause is used to specify the number of records to return.

-- Return first 5 records SELECT * FROM customers LIMIT 5; -- Skip first 2, return next 3 (MySQL/PostgreSQL) SELECT * FROM customers LIMIT 3 OFFSET 2; -- SQL Server syntax SELECT TOP 5 * FROM customers;

SQL Operators

SQL operators are used to perform operations on data in queries.

Logical Operators

OperatorDescriptionExample
ANDAll conditions must be trueage > 20 AND city = 'NYC'

Pattern Matching with LIKE

The LIKE operator is used with wildcard characters:

  • % - Represents zero or more characters
  • _ - Represents a single character
LIKE EXAMPLES

INSERT INTO Statement

The INSERT INTO statement is used to insert new records into a table.

INSERT Syntax

-- Insert all columns INSERT INTO table_name VALUES (value1, value2, value3, ...); -- Insert specific columns INSERT INTO table_name (column1, column2, column3) VALUES (value1, value2, value3);
INSERT EXAMPLES
-- Insert with all columns INSERT INTO customers VALUES (4, 'Alice', 'Brown', 'alice@email.com', 'Los Angeles'); -- Insert specific columns INSERT INTO customers (first_name, last_name, email) VALUES ('Bob', 'Wilson', 'bob@email.com'); -- Insert multiple rows INSERT INTO customers (first_name, last_name, email, city) VALUES ('Charlie', 'Davis', 'charlie@email.com', 'Chicago'), ('Diana', 'Miller', 'diana@email.com', 'Miami');

Inserting Data with SELECT

-- Copy data from one table to another INSERT INTO backup_customers (first_name, last_name, email) SELECT first_name, last_name, email FROM customers WHERE city = 'New York';
💡 Note: When inserting data, make sure the values match the column data types and constraints. String values should be enclosed in single quotes.

DELETE Statement and TRUNCATE TABLE

The DELETE statement is used to delete existing records from a table.

DELETE Syntax

-- Delete specific records DELETE FROM table_name WHERE condition; -- Delete all records DELETE FROM table_name;
DELETE EXAMPLES
-- Delete specific customer DELETE FROM customers WHERE customer_id = 5; -- Delete customers from a city DELETE FROM customers WHERE city = 'Boston'; -- Delete old orders DELETE FROM orders WHERE order_date < '2023-01-01';

TRUNCATE TABLE

The TRUNCATE TABLE statement is used to delete all records from a table, but keeps the table structure.

-- Truncate table (faster than DELETE for all records) TRUNCATE TABLE customers;
⚠️ Important: TRUNCATE cannot be rolled back in some databases. Use DELETE with WHERE for safer operations.

Difference between DELETE and TRUNCATE

FeatureDELETETRUNCATE

ALTER TABLE (Add, Modify, Drop Columns)

The ALTER TABLE statement is used to add, delete, or modify columns in an existing table.

Add Column

-- Add a new column ALTER TABLE table_name ADD column_name datatype constraint;
ADD COLUMN EXAMPLES
-- Add phone column ALTER TABLE customers ADD phone VARCHAR(20); -- Add column with default value ALTER TABLE employees ADD status VARCHAR(20) DEFAULT 'active'; -- Add column at specific position (MySQL) ALTER TABLE customers ADD middle_name VARCHAR(50) AFTER first_name;

Modify Column

-- Modify column data type or constraint ALTER TABLE table_name MODIFY column_name new_datatype new_constraint;
MODIFY COLUMN EXAMPLES
-- Change data type ALTER TABLE customers MODIFY phone VARCHAR(15); -- Add NOT NULL constraint ALTER TABLE employees MODIFY salary DECIMAL(10,2) NOT NULL; -- Change column name (different syntax per database) -- MySQL/PostgreSQL ALTER TABLE customers RENAME COLUMN phone TO phone_number;

Drop Column

-- Remove a column ALTER TABLE table_name DROP COLUMN column_name;
DROP COLUMN EXAMPLES
-- Remove middle_name column ALTER TABLE customers DROP COLUMN middle_name; -- Drop multiple columns (MySQL) ALTER TABLE customers DROP COLUMN fax, DROP COLUMN website;

GROUP BY Clause and HAVING

The GROUP BY clause groups rows that have the same values in specified columns.

GROUP BY Syntax

SELECT column1, aggregate_function(column2) FROM table_name GROUP BY column1;
GROUP BY EXAMPLES
-- Count customers by city SELECT city, COUNT(*) as customer_count FROM customers GROUP BY city; -- Average salary by department SELECT department, AVG(salary) as avg_salary FROM employees GROUP BY department; -- Total sales by product category SELECT category, SUM(sales_amount) as total_sales FROM products GROUP BY category;

HAVING Clause

The HAVING clause filters groups based on aggregate function results (similar to WHERE for groups).

SELECT column1, aggregate_function(column2) FROM table_name GROUP BY column1 HAVING aggregate_function(column2) condition;
HAVING EXAMPLES
-- Cities with more than 2 customers SELECT city, COUNT(*) as customer_count FROM customers GROUP BY city HAVING COUNT(*) > 2; -- Departments with average salary > 50000 SELECT department, AVG(salary) as avg_salary FROM employees GROUP BY department HAVING AVG(salary) > 50000;

Difference between WHERE and HAVING

WHEREHAVING
Filters rows before groupingFilters groups after grouping
Cannot use aggregate functionsCan use aggregate functions
Used with SELECT, UPDATE, DELETEUsed with GROUP BY

💡 Note: The most commonly used join is INNER JOIN. Always specify the join condition using ON or USING clause.

INNER JOIN

The INNER JOIN returns only the rows where there is a match in both tables.

INNER JOIN Syntax

SELECT columns FROM table1 INNER JOIN table2 ON table1.column = table2.column;
INNER JOIN EXAMPLES
-- Join customers and orders SELECT c.customer_id, c.first_name, c.last_name, o.order_id, o.amount FROM customers c INNER JOIN orders o ON c.customer_id = o.customer_id; -- Join with aliases SELECT c.name, p.product_name, oi.quantity FROM customers c INNER JOIN orders o ON c.customer_id = o.customer_id INNER JOIN order_items oi ON o.order_id = oi.order_id INNER JOIN products p ON oi.product_id = p.product_id;

Alternative Syntax (USING)

-- When column names are the same SELECT customer_id, first_name, order_id, amount FROM customers INNER JOIN orders USING (customer_id);

Visual Representation

LEFT JOIN and RIGHT JOIN

LEFT JOIN returns all rows from the left table and matching rows from the right table. NULL values appear for non-matching rows.

LEFT JOIN Syntax

SELECT columns FROM table1 LEFT JOIN table2 ON table1.column = table2.column;
LEFT JOIN EXAMPLES
-- All customers and their orders (if any) SELECT c.first_name, c.last_name, o.order_id, o.amount FROM customers c LEFT JOIN orders o ON c.customer_id = o.customer_id; -- Customers who haven't placed orders SELECT c.first_name, c.last_name FROM customers c LEFT JOIN orders o ON c.customer_id = o.customer_id WHERE o.order_id IS NULL;

RIGHT JOIN

RIGHT JOIN returns all rows from the right table and matching rows from the left table.

SELECT columns FROM table1 RIGHT JOIN table2 ON table1.column = table2.column;
RIGHT JOIN EXAMPLE
-- All orders and customer info (if available) SELECT o.order_id, o.amount, c.first_name, c.last_name FROM customers c RIGHT JOIN orders o ON c.customer_id = o.customer_id;

FULL OUTER JOIN and Self Join

FULL OUTER JOIN returns all rows from both tables, with NULL values where there are no matches.

FULL OUTER JOIN Syntax

-- Standard SQL SELECT columns FROM table1 FULL OUTER JOIN table2 ON table1.column = table2.column; -- MySQL (use UNION of LEFT and RIGHT JOIN) SELECT columns FROM table1 LEFT JOIN table2 ON table1.column = table2.column UNION SELECT columns FROM table1 RIGHT JOIN table2 ON table1.column = table2.column;
FULL OUTER JOIN EXAMPLE
-- All customers and all orders SELECT c.first_name, c.last_name, o.order_id, o.amount FROM customers c FULL OUTER JOIN orders o ON c.customer_id = o.customer_id;

Self Join

A Self Join is a join where a table is joined with itself.

SELF JOIN EXAMPLES
-- Employees and their managers (same table) SELECT e.employee_name, m.employee_name as manager_name FROM employees e LEFT JOIN employees m ON e.manager_id = m.employee_id; -- Find products with same category SELECT p1.product_name, p2.product_name, p1.category FROM products p1 INNER JOIN products p2 ON p1.category = p2.category WHERE p1.product_id < p2.product_id;

Cross Join

CROSS JOIN returns the Cartesian product of both tables (all possible combinations).

-- Cross join (be careful with large tables!) SELECT c.customer_name, p.product_name FROM customers c CROSS JOIN products p;

Subqueries (Nested Queries)

A subquery is a query nested inside another query. It can be used in SELECT, INSERT, UPDATE, or DELETE statements.

Types of Subqueries

  • Single-row subquery - Returns one value
  • Multi-row subquery - Returns multiple values
  • Correlated subquery - References outer query

Subquery in WHERE Clause

SUBQUERY EXAMPLES
-- Find customers with orders above average SELECT first_name, last_name FROM customers WHERE customer_id IN ( SELECT customer_id FROM orders WHERE amount > (SELECT AVG(amount) FROM orders) ); -- Find products more expensive than average SELECT product_name, price FROM products WHERE price > (SELECT AVG(price) FROM products);

Subquery in SELECT Clause

-- Add order count to each customer SELECT first_name, last_name, (SELECT COUNT(*) FROM orders WHERE customer_id = c.customer_id) as order_count FROM customers c;

Subquery in FROM Clause

-- Use subquery as a table SELECT category, total_sales FROM ( SELECT category, SUM(amount) as total_sales FROM products p JOIN sales s ON p.product_id = s.product_id GROUP BY category ) as category_sales WHERE total_sales > 1000;

Common Table Expressions (CTE) and UNION

Common Table Expressions (CTE) are temporary named result sets that exist within the scope of a SQL statement.

CTE Syntax (WITH Clause)

WITH cte_name AS ( SELECT columns FROM table_name WHERE condition ) SELECT columns FROM cte_name;
CTE EXAMPLES
-- Simple CTE WITH high_value_orders AS ( SELECT customer_id, SUM(amount) as total_amount FROM orders GROUP BY customer_id HAVING SUM(amount) > 500 ) SELECT c.first_name, c.last_name, h.total_amount FROM customers c JOIN high_value_orders h ON c.customer_id = h.customer_id; -- Recursive CTE (hierarchical data) WITH RECURSIVE employee_hierarchy AS ( SELECT employee_id, first_name, manager_id, 0 as level FROM employees WHERE manager_id IS NULL UNION ALL SELECT e.employee_id, e.first_name, e.manager_id, eh.level + 1 FROM employees e JOIN employee_hierarchy eh ON e.manager_id = eh.employee_id ) SELECT * FROM employee_hierarchy;

UNION and UNION ALL

UNION combines results from multiple SELECT statements. UNION ALL includes duplicates.

-- UNION (removes duplicates) SELECT city FROM customers UNION SELECT city FROM suppliers; -- UNION ALL (keeps duplicates) SELECT city FROM customers UNION ALL SELECT city FROM suppliers;
UNION EXAMPLES
-- Combine customer and supplier cities SELECT 'Customer' as type, city FROM customers UNION SELECT 'Supplier' as type, city FROM suppliers; -- Find all people (customers and employees) SELECT first_name, last_name, 'Customer' as role FROM customers UNION ALL SELECT first_name, last_name, 'Employee' as role FROM employees;

SQL Views

A view is a virtual table based on the result of a SELECT statement. It contains rows and columns, just like a real table.

Benefits of Views

  • Simplify complex queries
  • Provide security by restricting access to specific columns
  • Present data in different ways
  • Can be used to hide complexity

CREATE VIEW Syntax

CREATE VIEW view_name AS SELECT column1, column2, ... FROM table_name WHERE condition;
CREATE VIEW EXAMPLES
-- Simple view CREATE VIEW customer_orders AS SELECT c.customer_id, c.first_name, c.last_name, COUNT(o.order_id) as order_count FROM customers c LEFT JOIN orders o ON c.customer_id = o.customer_id GROUP BY c.customer_id, c.first_name, c.last_name; -- View with sensitive data hidden CREATE VIEW public_customer_info AS SELECT first_name, last_name, city, email FROM customers; -- Complex view with calculations CREATE VIEW sales_summary AS SELECT p.category, COUNT(*) as products_count, SUM(p.price * s.quantity) as total_sales, AVG(p.price) as avg_price FROM products p JOIN sales s ON p.product_id = s.product_id GROUP BY p.category;

Using Views

-- Query a view like a regular table SELECT * FROM customer_orders WHERE order_count > 5; -- Join with views SELECT co.*, ci.city FROM customer_orders co JOIN customer_info ci ON co.customer_id = ci.customer_id;

Modifying Views

-- Update view definition CREATE OR REPLACE VIEW customer_orders AS SELECT c.customer_id, c.first_name, c.last_name, c.email, COUNT(o.order_id) as order_count FROM customers c LEFT JOIN orders o ON c.customer_id = o.customer_id GROUP BY c.customer_id, c.first_name, c.last_name, c.email; -- Drop view DROP VIEW customer_orders;

Window Functions

Window functions perform calculations across a set of rows related to the current row, similar to aggregate functions but without grouping.

Window Function Syntax

SELECT column1, column2, window_function() OVER ( PARTITION BY partition_column ORDER BY order_column ROWS/RANGE frame_clause ) as alias FROM table_name;

Ranking Functions

FunctionDescriptionExample Result

DENSE_RANK()Rank without gaps1, 2, 2, 3...
NTILE(n)Divide into n groups1, 1, 2, 2, 3...
RANKING FUNCTION EXAMPLES
-- Rank employees by salary SELECT first_name, last_name, salary, ROW_NUMBER() OVER (ORDER BY salary DESC) as row_num, RANK() OVER (ORDER BY salary DESC) as rank, DENSE_RANK() OVER (ORDER BY salary DESC) as dense_rank FROM employees; -- Rank within departments SELECT department, first_name, last_name, salary, RANK() OVER (PARTITION BY department ORDER BY salary DESC) as dept_rank FROM employees;

Transactions

A transaction is a sequence of SQL statements that are treated as a single unit of work.

  • Durability - Changes persist after commit

SQL Injection and Security

SQL injection is a code injection technique that exploits vulnerabilities in an application's software by inserting malicious SQL code.

What is SQL Injection?

SQL injection occurs when user input is not properly sanitized and gets executed as part of an SQL query.

VULNERABLE CODE EXAMPLE
// Vulnerable PHP code $username = $_POST['username']; $password = $_POST['password']; $query = "SELECT * FROM users WHERE username = '$username' AND password = '$password'"; $result = mysqli_query($conn, $query); // Malicious input: ' OR '1'='1 // Results in: SELECT * FROM users WHERE username = '' OR '1'='1' AND password = ''

SQL Injection Attack Types

Attack TypeDescriptionExample
TautologyAlways true condition' OR '1'='1
Union-basedCombine results' UNION SELECT password FROM users --
Error-basedCause database errors' AND 1=CONVERT(int,@@version) --
BlindNo visible results' AND (SELECT COUNT(*) FROM users) > 0 --

Prevention Techniques

1. Prepared Statements

// PHP with prepared statements $stmt = $conn->prepare("SELECT * FROM users WHERE username = ? AND password = ?"); $stmt->bind_param("ss", $username, $password); $stmt->execute();

2. Parameterized Queries

// .NET example string query = "SELECT * FROM users WHERE username = @username AND password = @password"; SqlCommand cmd = new SqlCommand(query, conn); cmd.Parameters.AddWithValue("@username", username); cmd.Parameters.AddWithValue("@password", password);

3. Input Validation

// Sanitize input function sanitizeInput($input) { $input = trim($input); $input = stripslashes($input); $input = htmlspecialchars($input); return $input; }

4. Stored Procedures

-- Use stored procedures CREATE PROCEDURE AuthenticateUser(@username VARCHAR(50), @password VARCHAR(50)) AS BEGIN SELECT * FROM users WHERE username = @username AND password = @password; END;

Other Security Best Practices

  • Use least privilege principle for database users
  • Encrypt sensitive data (passwords, PII)
  • Regular security audits and penetration testing
  • Keep database software updated
  • Use firewalls and access controls
  • Log and monitor database activity

Password Security

SECURE PASSWORD STORAGE
-- Hash passwords before storing INSERT INTO users (username, password_hash, salt) VALUES ('john', SHA2(CONCAT('password123', 'randomsalt'), 256), 'randomsalt'); -- Verify password SELECT * FROM users WHERE username = 'john' AND password_hash = SHA2(CONCAT('entered_password', salt), 256);
⚠️ Critical Security Note: Never store plain text passwords. Always use strong hashing algorithms like bcrypt, scrypt, or Argon2 with unique salts.
